# 제어스킬 실험기 v3.11.0

하나의 실행기에서 보스·패턴 프로필을 선택하고 편집한다. 베스퍼의 기존 구간·기준값·문구 템플릿을 보존했다. 새 보스의 시각·문구는 별도 교정하며 베스퍼 값을 검증된 새 보스 설정으로 취급하지 않는다. 제품 웹앱과 분리된 연구 도구다.

## 비채점 보조 입력

모든 프로필에서 `보조 입력 추가`로 Space·RMB·LMB를 원하는 구간에 넣을 수 있다. 문구 기준 시각과 유지 시간을 50ms 단위로 입력한 뒤 `사용`을 체크한다. 새 행은 꺼진 상태이며 시각은 직접 지정해야 저장된다. 사용 체크를 끄면 행을 보존하면서 실행에서 제외하고, 선택 행 삭제로 제거한다. 설정은 자동 저장되며 실행 중에는 편집할 수 없다.

환영의 화살 유닛에서는 본 대응의 4타 키를 RMB로 선택하고, 3타와 4타 사이에 보조 Space를 넣을 수 있다. 본 대응의 시각은 이동하지 않는다. 9월22일에는 문구 기준 보조 Space11200ms·유지100ms 뒤 RMB11950ms로 교대·완벽 대응한 영상을 확인했다. 이는 한 경로의 성공 관측이며 보조 입력의 허용 폭이나 모든 거리의 성공 보장은 아니다. 초기11400ms 후보는 현재 추가 실험 요청이 아니며, 종료한 실험을 다시 반복하지 않는다. 이후 다른 조건을 비교할 필요가 생기면 보조 입력 유무 외 본 대응 설정을 맞추고, 선행 실패 이후의 결과를 정상 경로 경계와 구별한다. 현재 저장된 프로필은 자동 변경하지 않는다.

화면의 비채점 보조 입력 영역은 세 부분이다. 시작 입력은 **F8 감시 시작 기준**, 기존 준비 대응과 중간 보조 입력은 **문구 첫 일치 기준**이다. `StartAttack`의 생략된 `Key`는 기존처럼 LMB5이며, `"Key":"E"`는 E1회만 허용한다. 예를 들어 `"StartAttack":{"Key":"E","AtMs":[500],"HoldMs":100}`은 F8 감시 시작부터 500ms에 E를 눌러 100ms 유지한다. 실제 시작 시각은 보스 근거로 정한다. 기존 쿠사리쿠 시작 공격·준비 시간표와 기록은 그대로 유지한다. 새 보조 입력은 방향키를 자동화하지 않으며 `AllowManualMovement`가 켜진 프로필의 수동 WASD와 병행한다.

사용 중인 보조 LMB/RMB/Space의 유지 구간이 다른 보조 입력·준비 RMB·선택한 본 대응과 겹치면 실행할 수 없다. F9·창 이탈·전송 실패 등에는 프로그램이 보유한 키를 해제한다. 보조 입력을 넣어도 진입+후속의 결과 자리 수는 그대로다. 보조 계획은 `ProfileSnapshot.AuxiliaryInputs`, 실제/가상 사건은 `AuxiliaryInputs`에 별도로 남기며 전송 완료를 게임 성공으로 평가하지 않는다.

신규 보조 행을 저장한 프로필은 `SchemaVersion=2`다. v3.10은 기존 v1과 v2를 모두 읽고, 보조 행을 삭제해도 저장된 v2를 유지한다. 기존 v1 프로필과 원시 회차를 일괄 변환하지 않는다. 이전 실행기는 v2를 거부하므로 보조 입력을 조용히 빠뜨리고 실행하지 않는다. 구형 수동 준비 허용(`ManualPreparationRmbUntilMs > 0`)과 사용 중인 새 보조 입력은 함께 설정할 수 없다. 현행 제공 프로필에는 이 수동 준비 허용이 없다.

`experiment:check`는 공통 가짜 입력 회귀를 한 번 실행하고 모든 제공 프로필의 9개 시간표 조합·편집기 스냅샷과 별도의 UI 캡처를 검사한다. 개별 명령의 범위는 아래 [감지와 무입력 검증](#감지와-무입력-검증)을 따른다. 모두 게임 입력 없이 검사하며 게임 성공을 증명하지 않는다.

## 빌드와 실행

```powershell
.\tools.ps1 experiment:build
.local/experiment-build/ControlExperiment.exe
```

처음에는 베스퍼 Execute_02를 열고, 이후 마지막으로 저장한 설정을 연다. 다른 프로필은 창의 목록·`프로필 열기`로 선택한다. 명시적 실행도 지원한다.

```powershell
.local/experiment-build/ControlExperiment.exe --profile tools/experiment/profiles/vesper-execute-01.json
.local/experiment-build/ControlExperiment.exe --profile tools/experiment/profiles/vesper-execute-02.json
```

동시에 하나의 창만 실행한다. 새 프로필의 실행 셀은 **각 행 기준값**, 실제 입력은 항상 미체크로 시작한다. 이후 행별 선택도 프로필에 저장하여 다시 연다. 녹화는 F8을 인지한 순간의 최근 OBS 관측으로 ON/OFF를 고정하며 결과 저장 시점에 다시 정하지 않는다. 화면의 `현재 녹화`와 결과 입력란의 `F8 녹화`를 구별한다. OBS를 실행하지 않는 실험도 허용한다.

1. 보스·패턴, 파티 순서·시작 캐릭터, 총 동작 수와 시각을 확인한다. 총 동작 수에는 진입이 포함된다. 기르타블리르 진입+3타는 4동작이다.
2. 진입을 포함한 모든 동작의 `키` 열에서 RMB/Space를 선택한다. 각 행의 이른·기준·늦은 셀 중 이번에 실행할 하나를 클릭한다. 조합 목록·A/B 그룹·별도 진입 키 옵션은 없다.
3. 사용자가 실제 게임 실험을 할 때만 입력 체크를 켠다. 해제 상태에서는 감지와 가상 입력 시각만 기록한다.
4. 문구 출현 전 **게임 창에서 F8**을 누른다. 쿠사리쿠는 WASD 직접 이동을 허용하고 좌클릭5회·준비 회피·진입·후속은 자동 수행한다. LMB·RMB·Space를 직접 추가하지 않는다. **F9**, 창 이탈·이동·크기 변경, 허용되지 않은 수동 입력은 중단 조건이다.
5. 종료 후 표시된 동작 수만큼 결과를 입력하고 `결과 확정·보관`을 누른다. **0 실패 / 1 성공**, 첫 자리는 진입이다. 4동작 전체 성공은 `1111`, 세 번째 실패는 `1101`이다. 정확한 길이와 0/1만 허용하며 전체 성공 버튼은 없다.

현재 회차는 종료 후 자동으로 결과 입력에 연결된다. 결과를 확정하지 않고 다음 회차를 시작하거나 정상 종료하면 해당 임시 로그·감지 이미지를 폐기한다. 비정상 종료로 남은 임시 회차도 다음 시작 때 정리한다. 다음 실행의 설정·대상 창 확인에 실패한 경우에는 이전 임시 회차를 유지한다. 관찰만 한 회차는 결과 입력 대상이 아니며 종료 시 임시 기록을 폐기한다. 기존 보관 로그·OBS 영상·공유 녹화 이력은 자동 삭제하지 않는다.

`최근 회차 정정`은 마지막으로 결과를 확정·보관한 회차 하나를 자동으로 연다. 파일이나 과거 회차를 선택하지 않는다. 시각·보스/패턴·진입 키·시작 캐릭터·입력 시각·현재 결과를 확인한 뒤, 수정할 항목에서 **성공/실패 결과** 또는 **시작 캐릭터**를 선택하고 `정정 저장`을 누른다. 결과는 표시된 동작 수만큼0/1을 입력하고 시작 캐릭터는 파티 목록에서 선택하거나 직접 입력한다. 과거 파일 정정 기능은 제공하지 않으며 사용자가 필요하면 수동으로 제거한다. 현재 프로필의 설정을 바꾸지 않고 해당 회차만 정정한다. 정정 창이 열린 동안F8 시작은 막는다.

## 환영의 화살 유닛 채택 설정 — 2026-09-22

**환영의 화살 유닛 / Attack_09**의 편성은 **아리아→남궁우→수나**, 시작은 **아리아**다. 자동20회와 기준 녹화2개를 거쳐 웹 기본 대응을 채택했다. bundled 프로필 기준은 진입 RMB4250ms, 후속 Space6400/8150/9550/11850ms이며 문구 최초 감지 기준이다. 성공 교차로 채택한 양끝과 관측 한계는 [현행 표와 근거](../../docs/experiments/arrow-unit-control-skill.md)를 따른다. 사용자 실행 위치의 편집한 프로필은 별도로 보존하며 웹 반영 때문에 자동 덮어쓰지 않는다. 최초 탐색을 반복할 필요는 없다.

문구 출현 전 F8을 누른다. 시작 LMB5회나 준비 RMB는 자동 실행하지 않는다. WASD는 직접 병행할 수 있고 RMB·Space는 프로그램이 입력한다. 첫 비교에서는 이동 조건을 일정하게 유지한다. 메뉴에서 복귀할 때 이미 문구가 떠 있는 경우는 새 문구 감지의 유효한 시작이 아니므로 다음 새 발동 전에 시작한다. 실제 입력 체크는 사용자가 직접 켠다. 결과는 진입부터5자리이며 완벽 대응 배너만으로11111을 기록하지 않는다.

## 쿠사리쿠 현행 실행 조건

현재 실제 사용 위치는 [README](../../README.md)의 f815 실행파일이다. **쿠사리쿠 / Execute_01**에서 다섯 행 모두 기준을 선택한다. v3.8 자동 시작 실험49회와 사용자가 제안한 구간을 연결하고, 실험 중 저장한 기준값을 확인하고2타는 중점7925에서 동률 이른 쪽인7900으로 정정했다. 최신 수동 이동 무피격 대표와 다섯 폭을 사용자가 채택했고 쿠사리쿠 실험을 종료했다. [최종 보고서](../../docs/experiments/kusarikku-control-skill.md)를 따른다.

|대응|이른/기준/늦은 ms|유지 ms|
|---|---|---:|
|준비 회피1|1250 고정|150|
|준비 회피2|2650 고정|150|
|진입 RMB|3950 / **4100** / 4250|100|
|1타 Space|6700 / **6850** / 7050|150|
|2타 Space|7700 / **7900** / 8150|200|
|3타 Space|9450 / **9650** / 9850|250|
|4타 Space|10550 / **10750** / 11000|200|

엽빛나→수나→자오·시작 엽빛나로 같은 시작 위치/목표를 맞춘다. **실제 입력 체크 → LMB·RMB·Space를 놓고 게임에서 F8 → 시작 LMB5회부터 전체 자동 대응** 순서다. WASD는 F8 전부터 계속 누르거나 도중 바꿔도 된다. 시작 좌클릭은 감시 루프 시작부터500/1050/1700/2300/3100ms에 누르고 각각100ms 유지한다. 간격550/650/600/800ms는16-29-13의 수동5누름을50ms로 옮긴 후보다. F8 인지 후 설정 저장·창 확인 시간이 있으므로 물리F8부터의 정확한 시간표는 아니다. 문구 뒤 준비·진입·후속 시각은 기존 감지 원점을 유지한다.

쿠사리쿠의 `AllowManualMovement=true`는 WASD 중단 조건만 해제한다. 프로그램은 방향키를 누르거나 떼지 않으며 F9·오류 때도 직접 누른 WASD를 보존한다. 자동 방향 준비와 함께 설정할 수 없고 생략된 기존 프로필은 기존 정책을 유지한다. 시작 공격 중에도 문구를 감지하며,5회 해제 완료 전의 첫 일치가 확정되면 남은 클릭을 보내지 않고 중단한다. 확정 시각만 늦어져도 첫 일치가 해제 전이면 중단한다. 실제 입력 체크를 끄면 시작 공격도 가상 기록만 남기며 게임에 보내지 않는다. 자동 A→D→A 이동은 없고 실제 입력 체크는 프로그램을 열 때 꺼져 있다.

쿠사리쿠 서비스 채택 후 실험은 종료했으며 결론은 [최종 보고서](../../docs/experiments/kusarikku-control-skill.md)에 연결한다. 기존13조건을 처음부터 반복하지 않는다. 수동 이동을 비교하려면 이동 경로를 고정해 전체 기준1회부터 확인하고 기존 무방향 실험과 구별한다. 작은 준비 피해만으로 전체 재현을 자동 실패 처리하지 않지만 무피격 성공으로 기록하지 않는다. 준비 표의 시작·유지는50ms 단위로 편집·자동 저장된다. 본 대응의 `유지 ms`와 시작LMB 시간표는 프로필에 지정된 값이며 저장/회차 스냅샷에 보존한다. 시각 변경은 유지시간을 변경하지 않는다.

다섯 자리 결과의 첫 자리는 진입, 나머지는1~4타다(`11111`=진입 이후 전체 성공). 준비 피격·경직이나 경로 이탈은 이 다섯 자리에 포함되지 않으므로 그런 일이 있으면 결과 입력란의 선택 메모에 적는다(최대500자). 정상 회차마다 별도 설명은 필요 없으며 빈 메모를 준비 성공으로 해석하지 않는다. 결과 보관 때 같은 회차의 결과 sidecar에 사용자 보고로 저장한다. `최근 회차 정정`의 `준비 문제 메모`에서 수정·삭제할 수 있고, 결과만 고치거나 시작 캐릭터를 정정해도 메모는 유지한다. 준비가 없는 과거 회차에는 메모란이 나타나지 않는다. 준비 계획은`ProfileSnapshot.Preparation`, 실제 전송은`PreparationInputs`에 진입 이후 입력과 분리해 기록하며, 전송 완료를 게임 성공으로 표시하지 않는다.

자동 준비 중 F9·창 이탈·입력 오류가 생기면 프로그램이 보유한 방향·대응 키를 해제하고 중단한다. 감지 확정이 첫 준비 시각보다50ms 넘게 늦으면 뒤늦은 준비를 몰아 실행하지 않고 중단한다. 기존 수동 준비 프로필의`ManualPreparationRmbUntilMs`는 계속 읽지만, 자동 준비와 동시에 사용할 수 없고 현행 쿠사리쿠 값은0이다. 전체 기준 성공을 먼저 확인하고 실패하면 문구·준비 피격·선행 대응부터 구별한다. 세부 묶음과 변경 조건은 [쿠사리쿠 조사](../../docs/experiments/kusarikku-control-skill.md)를 따른다.

## 최근 보관 회차

창 아래에서 마지막으로 결과를 보관한 회차 하나의 시각·보스/패턴·파티·시작 캐릭터·녹화·결과와 동작별 키·실행에 사용한 설정ms를 읽기 전용으로 확인한다. 앱을 열 때, 결과 보관·정정 뒤 갱신한다. 현재 편집값과 섞거나 자동으로 적용하지 않는다. 결과 미입력 임시 회차는 이 영역을 덮어쓰지 않는다. 후보값과 선택 열은 표시하지 않으며 실행 설정ms는 당시 로그값이다. 오래된 회차 선택·설정 가져오기 버튼은 제공하지 않는다.

## 프로필과 편집

총 동작 수는 선택한 보스·패턴 프로필에서 자동으로 정하고 화면에는 읽기 전용으로 표시한다. 내부 프로필 형식은 1~12동작을 지원하며 사용자가 타수를 줄이거나 늘릴 필요는 없다. 시각은 직접 숫자를 입력하거나, 이른 값·기준값·늦은 값 중 셀 하나를 선택한 뒤 공통 `− 50 ms` / `+ 50 ms` 버튼으로 조정한다. 다른 셀은 바뀌지 않는다. `키` 열에서 진입부터 마지막까지 각 동작의 RMB/Space를 설정하고 자동 저장한다. 키를 바꾸어도 시각은 자동으로 바뀌지 않는다. 숫자 셀을 한 번 클릭하면 해당 행의 실행값이 되고 녹색·굵은 글씨로 표시한다. 두 번 클릭 또는 Enter/F2로 숫자를 편집한다. 키보드 화살표는 포커스만 옮기며 Space로 실행 셀을 선택한다. ±50ms는 포커스가 있는 숫자 셀을 선택하고 수정한다. `이번 입력 ms`는 각 행의 선택 결과다. 포커스가 다른 행으로 이동해도 실행값 강조는 유지된다. 이른 값≤기준값≤늦은 값과 50ms 단위(기술적 예약 범위 100~120000ms)를 검사한다. 최소 간격·허용 최소/최대 편집 항목은 제거했다. 기존 JSON의 MinimumSpacingMs·MinimumMs·MaximumMs는 과거 형식을 읽기 위해 남기지만 탐색 제한에 사용하지 않는다. 실행할 조합의 순서와 앞 동작의 키 유지 충돌을 검사하며 다른 조합의 극단값 때문에 후보를 저장하지 못하게 하지 않는다. `문구 감지 설정`에서 템플릿 경로·영역·임계값 등을 편집할 수 있다. 현재 감지는 노란 글자 모양 일치 방식이며 다른 색·방식의 감지가 템플릿 추가만으로 해결된다고 보장하지 않는다.

프로필은 **보스·패턴을 중심으로 한 실험 설정 묶음**이다. 문구 감지 조건, 동작 목록·시각·대응별 키, 파티 순서·시작 캐릭터·환경을 포함한다. 파티를 바꾼다고 자동으로 새 프로필이 생기지는 않는다. 같은 보스·패턴에서도 파티별 설정을 따로 유지하려면 `다른 이름 저장`으로 별도 파일을 만든다. 프로필 ID가 같아도 파일 이름으로 설정 묶음을 구별하며 각 회차에 실제 설정 스냅샷을 보존한다.

유효한 입력을 마치면 약0.6초 뒤 설정을 자동 저장하고 화면에 저장 상태를 표시한다. 잘못된 숫자·순서는 미저장 이유를 표시하며 바로잡은 뒤 저장한다. F8·프로필 전환·정상 종료 때도 저장한다. 설정 기억과 회차 결과 보관은 별개이므로 `프로필 저장` 버튼은 제거했다. 기본 제공·외부 프로필은 실행 파일 옆 `profiles`에 편집본을 만들며 같은 이름의 다른 저장본이 있으면 별도 파일명으로 보존한다. `다른 이름 저장`으로 지정한 파일에는 이후 편집도 계속 자동 저장한다. 기본 제공 정본을 자동으로 덮어쓰지 않는다. 같은 파일명·보스·패턴·ID의 유효한 저장본이 있으면 목록에 저장본만 표시하고 기본 제공본은 숨긴다. 다른 이름 저장한 변형은 ID가 같아도 유지한다. 템플릿은 내용 해시를 이름으로 함께 저장한다. 실행 중에는 프로필·키·시각·파티 편집을 잠근다.

각 Actions의 `SelectedTiming`은 early/baseline/late이며 생략된 구형 프로필은 baseline으로 읽는다. 신규 회차에는 `Pattern=per-action`, `SelectedTimings`, `ActionKeys`, `DelaysMs`와 프로필 스냅샷을 남긴다. 구형 회차·그룹 조합 읽기는 유지하지만 UI에서는 제공하지 않는다. `SchemaVersion=1/2` JSON은 에이전트도 같은 형식으로 읽고 편집할 수 있다. `ProfileStore.Validate`가 시작 전에 검사한다. 새 보스는 AI가 근거에 따라 보스·프로필 ID, 감지 조건과 후보를 준비하고 무입력 검증한 뒤 사용한다. 사용자가 JSON을 직접 작성할 필요는 없다.

기본 제공 설정은 [프로필 폴더](profiles), 채택 이유·예외는 [베스퍼 보고서](../../docs/experiments/vesper-control-skills.md)와 [기르타블리르 보고서](../../docs/experiments/girtablullu-control-skill.md)를 따른다. 두 보스의 실험·서비스 반영은 종료했으며 초기 후보나 과거 비교 순서를 재실행 지시로 사용하지 않는다. 다음 행동은 [README](../../README.md)가 정본이다.

이른/늦은 서비스 구간, 실험의 기준 셀, 영상에서 관측한 입력 참조는 역할이 다르다. 영상과 숫자를 맞추려고 기준값을 바꾸지 않는다. 실행 파일 옆 `profiles`에 저장된 사용자 편집값·선택 셀은 유지하며 기본 제공값으로 되돌리지 않는다. 실제 회차는 당시 스냅샷과 실행 설정으로 분석한다. 기본 제공 프로필은 `experiment:check`가 모두 무입력 검사하며, 서비스 영상이 없는 연구 후보도 허용한다. 프로그램 검사는 실제 게임 성공 구간의 검증이 아니다.

## OBS 자동 관측

OBS의 **도구 → WebSocket 서버 설정**에서 v5 서버를 켠다. 표준 OBS 설정 파일이 있으면 주소·인증정보를 읽고 시작 시 연결한다. 없거나 다른 환경이면 `OBS 연결 설정`에 주소·비밀번호를 한 번 입력한다. 저장된 비밀번호는 현재 Windows 사용자 DPAPI로 보호하며 회차 로그에는 남기지 않는다. OBS 설정·녹화 시작·종료는 프로그램이 변경하지 않는다.

v3.2.1부터 **F8을 인지한 순간**의 최근 OBS 상태를 복사하고 회차 녹화 여부를 고정한다. F8 이후 녹화를 중지하거나 결과 저장 때 OFF가 되어도 해당 회차의 ON은 바뀌지 않는다. 반대로 F8 때 OFF이면 나중에 녹화를 켜도 해당 회차는 OFF다. 표시된 `현재 녹화`는 실시간 상태이고, 결과 입력란의 `F8 녹화`는 고정된 회차 상태다.

사용자 지시에 따라 미연결·관측 만료 등 **UNKNOWN은 OFF로 취급**한다. 일시정지도 F8 순간에는 OFF로 취급한다. 녹화하지 않을 때 OBS를 실행할 필요는 없다. 실제 OBS 원관측과 이 운영 정책은 로그에서 구별한다. 녹화를 켜서 비교할 때는 F8 전에 `현재 녹화 ON`을 확인한다. OBS를 나중에 실행했다면 `다시 연결`로 연결할 수 있다.

상태 이벤트와 2초 간격 조회를 사용하며, 3초 넘게 갱신되지 않은 관측은 UNKNOWN이다. F8 처리는 새 OBS 응답이나 녹화 이력 파일 저장을 기다리지 않고 메모리에 전달된 최근 관측을 사용한다. OBS 변경 이력은 영상 연결을 위해 유지하지만 회차 분류를 덮어쓰지 않는다. 녹화 상태 정정으로 원본의 F8 관측을 다시 쓰지 않는다. 분석에서 과거 UNKNOWN도 사용자 정책 OFF로 분류하되 출처를 정책 적용으로 명시하며, 수동 정정이 있으면 우선한다. 과거 MIXED는 그대로 두며 과거 회차를 새 F8 스냅샷처럼 표현하지 않는다.

실행 파일 옆 `obs-recordings/<RecordingId>.json`에 관측 이력과 영상 경로를 남긴다. 한 영상에 여러 회차가 있어도 ID로 연결한다. 녹화 파일 경로는 보통 OBS 녹화 종료 이벤트에서 확보되므로 **녹화 종료까지 실험기를 열어 둔다**. 종료 전에 실험기를 닫거나 연결이 끊기면 그 파일 경로는 미확인으로 남으며 재연결 뒤 영상을 추측해 이어 붙이지 않는다. 일시정지 이력의 벽시계 시간을 영상 시각으로 그대로 빼지 않는다. 영상 파일 부재만으로 OFF를 판정하지 않는다.

## 기록과 분석 연결

실행 중에는 실행 파일 옆 `pending-trials`에 임시 회차를 쓴다. 올바른 결과를 확정할 때만 `notice-logs`에 회차 JSON·결과 JSON·감지 PNG를 보관한다. 파일은 고유 이름이며 내부 TrialId·시작 시각·프로필 스냅샷으로 회차를 식별한다. 두 JSON은 한 회차의 입력 증거와 사용자 결과이고 중복 회차가 아니다. 확정 도중 오류가 나면 임시 회차를 유지해 재시도할 수 있다.

- `ProfileSnapshot`, `ProfileHash`: 실제 적용한 설정과 그 직렬화 해시. `SourceProfilePath`/`SourceProfileHash`는 읽은 파일의 위치·바이트 해시다.
- `ProfileSnapshot.StartAttack`, `StartAttackInputs`: 문구 이전 시작 LMB5 또는 E1 계획과 전송/가상 사건. 시각 원점은 감시 루프 시작이며 문구 원점의 준비/본 대응과 구별한다. 시작 입력은 결과 자리에 포함되지 않는다. `StartAttack` 없는 기존 프로필은 자동 시작 입력을 하지 않는다. 원시 필드명은 유지되며 실제 사건의 `Key`가 LMB/E를 구별한다.
- `ProfileSnapshot.AllowManualMovement`: 수동 WASD 허용 여부다. 실제 이동 여부·시각·경로를 기록한 값은 아니며 기존 무방향 실험과 조건을 구별하는 데 쓴다.
- `ActionIds`/`ActionKeys`, `Candidates`/`DelaysMs`, `Party`/`StartCharacter`: 해당 회차의 순서·키·시각·파티 조건.
- `F8Utc`, `RecordingAtF8`, `RecordingBasis`, `Recording`: F8 인지 시각·복사한 관측·분류 정책과 고정된 회차 ON/OFF. UNKNOWN→OFF는 관측 성공이 아니라 승인된 운영 정책이다.
- `ObsObservations`, `ObsLedgerDirectory`: 이후 OBS 관측·영상 세션 자료 연결. 결과 확정이나 정정으로 F8 값을 다시 측정하지 않는다.
- `StartedUtc`/`EndedUtc`, `Samples`/`Inputs`: 문구 감지·예약·실제 제출·중단 근거. `GameOutcome=미확인`은 원시 입력 로그 자체가 게임 성공을 판정하지 않는다는 뜻이다.

임시 회차에서 armed→detected→종료 상태를 기록한다. 확정할 때 감지 이미지 경로를 최종 보관 위치로 연결하고 원본 해시를 계산한다. 결과는 `<원시파일>.result.json`에 원본 해시·TrialId와 함께 저장한다. 원본의 감지·입력 시각·녹화·설정 스냅샷은 유지한다. 사용자가 시작 캐릭터를 정정하면 원본의 최상위 `StartCharacter`만 수정하고 결과 파일의 원본 해시를 함께 갱신한다. `ProfileSnapshot.StartCharacter`는 당시 저장 설정이므로 그대로 남으며, 분석은 실제 회차의 최상위 값을 사용한다. 결과 파일의 `startCharacterCorrections`에는 이전/이후 값과 해시·정정 시각을 남긴다. 저장 중 중단되면 다음 접근에서 두 파일을 복구한다. 분석 저장소에 이미 등록한 회차는 다시 가져오면 검증된 캐릭터 정정만 반영하고 기존 결과·수동 주석을 유지한다. 같은 결과 재저장은 중복 이력을 만들지 않고 다른 값으로 정정하면 이전 값을 남긴다. 삭제한 원본을 결과 저장으로 복원하지 않는다.

사용자는 프롬프트나 JSON에 파티·녹화·결과를 다시 적을 필요가 없다. controller는 필요한 완료 회차를 기존 명령으로 분석 저장소에 가져온다.

```powershell
.\tools.ps1 experiment:records import --raw <종료된-회차.json>
.\tools.ps1 experiment:records summary
.\tools.ps1 experiment:records validate
```

import는 결과 sidecar와 OBS 자료를 함께 읽는다. 결과 정정·뒤늦게 확보된 영상 경로는 같은 회차를 재import하면 반영된다. 명시적인 수동 녹화 정정이 있으면 우선하고 없으면 OBS 관측을 사용한다. OBS 출처는 사용자 보고와 분리한다. 선행 실패 뒤 결과는 정상 경로와 분리하며 OS 입력 제출을 게임 성공으로 바꾸지 않는다. 별도 영상 판독·실험 묶음은 `experiment:records help`의 기존 서식을 controller가 작성한다.

## 감지와 무입력 검증

베스퍼의 1280×720 기준 문구 영역은 x368/y136/너비528/높이28, 임계값0.68이다. 부재100ms 뒤 새 일치40ms를 확인하고 **최초 일치 캡처 종료**를 원점으로 쓴다. 확인40ms를 다시 더하지 않는다. 모든 입력은 공통 원점에서 예약하며 앞 입력 완료에 따라 후속 예약을 이동하지 않는다. API 반환 뒤 동작별 HoldMs만큼 유지(누락된 기존 프로필은80ms), 캡처·분석100ms 초과 중단, 예약50ms 초과 지각 중단을 유지한다.

```powershell
.\tools.ps1 experiment:check
```

가짜 입력·동적 창, 설정 저장·다른 프로필 전환, 1/12동작 프로필 전환 시 시각 보존, 진입 키, 결과 길이·정정·원본 불변, 모의 OBS 인증·ON/OFF·pause·단절·늦은 파일 연결, 기존 미디어 정렬을 검사한다. 실제 게임 입력이나 OBS 녹화 제어를 하지 않는다. `--notice-test`, `--ui-smoke`, `--notice-replay`, `--notice-capture-test`도 유지한다. `--notice-replay` 인수는 `<roi.rgb> <report.json> <first-low> <first-high> <last-high>`이며 60fps의 0기준 프레임이다. 자동 검사 통과는 실제 OBS 환경 연결·새 보스 문구 감지·게임 성공 검증과 구별한다.

프로필을 지정하는 명령은 `ControlExperiment.exe --profile <profile.json>` 뒤에 다음 인수를 붙인다. 보고서·캡처를 저장할 부모 폴더는 먼저 준비한다.

| 변경·확인할 범위 | 인수·완료 근거 |
|---|---|
| 개별 프로필 시각·키·설정 | `--profile-check <report.json>`: 9개 시간표와 편집기 설정 스냅샷, 프로필 ID·해시. 공통 회귀를 반복하지 않음 |
| 편집기 화면·레이아웃 | `--ui-smoke <image.png>`: 별도의 실제 창 캡처. 위 설정 검사가 시각 검토를 대신하지 않음 |
| 공통 예약·입력·중단 동작 | `--notice-test <report.json>`: 선택 프로필 검사와 공통 가짜 입력 회귀 |
| 새 문구 감지·영상 원점 | `--notice-replay <roi.rgb> <report.json> <first-low> <first-high> <last-high>`: 사람이 확인한 출현 범위와 저장 영상 감지를 대조 |

승인된 후보를 적용할 때는 소유한 대상 프로필에 저장하고 실제 사용할 실행파일과 프로필 경로로 검사한다. 보고서의 ID·해시와 로드한 시각·키·파티·시작 캐릭터를 대조해야 실행 준비가 끝난다. 기존 사용자 편집본은 명시된 변경만 적용하며 원시 회차의 스냅샷은 바꾸지 않는다. 실행파일을 갱신할 때는 대상 경로와 관련 설정의 전후 보존을 확인한다. 웹 전용 수정에는 실행파일 배포나 설정 해시 검사를 반복하지 않는다.

공통 실행부를 포함한 통합 검사는 controller가 변경을 모은 뒤 한 번 수행한다. worker마다 전체 명령을 반복하지 않으며 통과 뒤 새 변경·실패가 없으면 재실행하지 않는다. 변경별 웹·문서 검사 범위는 [README](../../README.md#변경에-맞춘-검증)를 따른다.
