# 입력 레인 검증기

`LaneVerifier.exe`를 실행합니다. 기존 자동 입력용 `ControlExperiment.exe`는 먼저 종료합니다. 이 프로그램에는 자동 입력 기능이 없습니다.

1. 대상 보스·패턴과 진입 키를 고릅니다. 첫 검증은 베스퍼 Execute_01, 우클릭 진입을 권합니다. 표의 구간은 채택된 실험값이며 영상 원점 보정은 넣지 않습니다.
2. ZZZ를 창모드 16:9, 게임 내부 화면 1280×720 이상으로 배치합니다. 제목 표시줄 크기는 제외합니다. 게임 창을 화면 안에 두고 안내 문구를 다른 창으로 가리지 않습니다.
3. 게임 창에서 문구가 나오기 전에 F8을 누릅니다. 감지를 준비한 뒤에도 준비 전투를 직접 조작할 수 있습니다. 새 문구가 인식되면 게임 창 하단에 레인이 나타납니다.
4. 타일이 왼쪽20%의 흰 입력선과 겹치는 동안 해당 키를 직접 누릅니다. 타일 전체가 허용 구간이며 가운데를 반드시 맞출 필요는 없습니다. 게임 포커스를 유지하며 레인 위 클릭도 게임으로 통과합니다.
5. 마지막 동작이 지나면 레인이 사라집니다. 이 창으로 돌아와 실제 게임에서 확인한 결과를 진입부터 0/1로 입력하고 **결과 보관**을 누릅니다. 베스퍼01은6자리, 베스퍼02는5자리, 기르타블리르는4자리입니다. 레인의 초록색은 레인 구간 내 입력이며 게임의 완벽 대응을 뜻하지 않습니다.

F9 또는 ESC, 게임 창 포커스 이탈, 창 이동·크기 변경 시 중단합니다. 프로그램은 F8/F9/ESC 입력을 차단하지 않습니다. 실제 게임에서도 해당 키가 동작할 수 있습니다. 게임 창 배치는 F8 전에 끝내세요.

OBS는 필요 없습니다. 성공 여부 미입력 회차는 메모리에만 있고 다음 F8·프로필 변경·종료 때 폐기합니다. 기존 보관 결과는 유지합니다. `results` 폴더의 JSON에는 문구 감지 점수·첫 감지 원점, 프로필·템플릿 해시, 직접 입력 시각, 레인 내부 판정, 그리기 시각과 게임 결과가 함께 저장됩니다. 중단 회차는 게임 실패 표본으로 보관하지 않습니다.

입력 시각은 OS의 수동 입력을 관찰한 훅 시각입니다. 물리 스위치 시각이나 게임 내부 처리 시각은 아닙니다. 그리기 기록 역시 프로그램이 그린 시각으로 모니터 표시 지연과 다릅니다. 창 크기를 바꾼 실제 게임의 최초 감지 시점·대응 성공은 첫 사용자 검증에서 확인해야 합니다.

프로필·템플릿 폴더를 실행파일과 함께 유지하세요. 기존 실험기 프로필·웹 영상·웹 판정 구간은 변경하지 않습니다. `--self-test <폴더>`와 `--smoke <폴더>`는 가짜 창·무입력 검사 전용입니다.


## 게임과 레인을 함께 녹화하기

2026-09-20 설정한 OBS 장면 모음 `ZZZ Recording`의 **레인 검증** 장면을 사용합니다. 기존 `ZZZ - 입력 분석 녹화` 장면은 그대로 남아 있습니다.

1. `녹화 시작 - 720p60`으로 OBS를 실행하고 `레인 검증` 장면을 선택합니다. 현재 모니터 전체를 하나의 디스플레이 캡처로 담으며 출력은 1280×720, 60fps입니다. ZZZ 소리는 별도의 응용 프로그램 오디오 소스로 연결되어 있습니다.
2. ZZZ를 창모드로 배치하고 검증기에서 패턴을 고릅니다. 게임과 하단 레인이 화면 밖으로 나가지 않게 합니다.
3. OBS에서 녹화를 시작한 뒤 OBS 창을 최소화합니다. 게임으로 돌아가 문구 출현 전에 F8을 누르고 직접 대응합니다. 감지 후 나타나는 레인과 게임이 같은 화면 캡처에 담깁니다.
4. 패턴이 끝나면 녹화를 종료하고 검증기에 게임 결과를 보관합니다. 같은 회차의 영상과 results JSON을 함께 분석합니다.

이 장면은 모니터 전체를 녹화하므로 다른 창이 게임이나 레인을 가리지 않게 하세요. 설정 완료 시 녹화는 자동 시작하지 않습니다. 녹화는 정렬 조사용이며 녹화 OFF의 성공 구간을 변경하는 근거로 단독 사용하지 않습니다.

검증기의 Execute_01 늦은 값은 3타 9750ms, 4타 11150ms로 웹과 맞췄습니다. 나머지 구간·기준값·감지 원점은 유지합니다.
