## 해석 모델과 제품 반영 원칙

사용자와 합의한 작업 가설은 `성공 입력 폭 ≈ 보스 측 구간의 시간 폭 + 캐릭터 판정 유지시간의 기여`다. 서로 다른 내부 단위에는 `A·x + B·y` 형태의 환산을 둘 수 있다. 회피와 패링을 같은 폭으로 강제하지 않되, 모든 회피200ms·모든 패링450ms라는 보편 규칙도 만들지 않는다.

예시식 `250=30x+9y`, `475=32x+50y`의 해는x≈6.78630, y≈5.15677이다.250/475는 경계 여유를 추정해 보충한 값이며 선택한 연습 폭200/450과 다르다.9도0.15초를 명목60fps로 표현한 값이다. 이 맞춤 계산 자체가 엔진 시간식의 검증은 아니다. 후속 실험의 예측과 비교하면서 필요할 때 수정한다.

이전 controller의 읽기 전용 점검은 회피도 캐릭터frame0에서 감지체를 켜며 기본수명0.15와 종료·제거 경로를 함께 봐야 한다고 확인했다. 남궁우 패링의L/H시작0~50에는 제어 상태가 연결되고 지원 시작·상태 추가에서 특수모드 진입, 패링 피격·상태 제거에서 종료하는 설정이 있다.0.15와0~50을 직접 비교하거나 단순 교대와 방어 지원을 동일시하지 않는다. 자세한 정적 근거는 [연구 기록](research-history.md#지원-창과-실제-입력의-기본-코드-경로)에 있다.
