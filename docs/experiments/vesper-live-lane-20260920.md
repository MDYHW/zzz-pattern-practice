## 지연과 영상 정렬

수동 입력의 훅→UI 처리 시간은 중앙값 11.78ms, 최대 30.50ms다. 판정은 UI에서 처리한 시각이 아닌 훅에서 수집한 시각을 사용하므로 이 대기를 입력 시각에 더하지 않는다. OS 이벤트→훅은 0~16ms이나 거친 정수 시계 기록이며 물리 키→게임 수신 지연 측정이 아니다.

페인트 간격은 중앙값 28.97ms, p95 36.48ms다. 현재 기록상 16ms 타이머 설정이 매끄러운 60fps 표시로 이어지지는 않았다. 그리기 자체는 중앙값 2.90ms다. 개선할 여지는 있지만 좌표는 매 그리기 현재 절대 시각으로 계산하므로 누적 타이머 드리프트와 구별한다. 124.51ms의 가장 긴 공백은 14:12:47 회차 원점+6750~6875ms에서 발생했다. 최초 실패 6186ms보다 뒤라 그 실패의 직접 원인으로 볼 수 없다.

OBS의 해당 실패 영상에는 렌더링 지연 16프레임(0.9%)이 기록됐다. 발생 시각은 없으므로 첫 실패와의 인과를 확정하지 못한다. 다른 연결 영상은 렌더링 지연 보고 없음 또는 2~3프레임(0.1~0.2%)이었다. 녹화가 원인이라는 증거도, 녹화 영향이 없다는 증거도 충분하지 않다.

녹화는 1280×720·60fps의 게임 캡처와 별도 키 오버레이다. 검증 레인은 녹화에 포함되지 않아 실제 모니터에 제시된 레인의 지연을 영상에서 직접 측정할 수 없다. 식별 가능한 키 표시의 상승 프레임 24개를 로그와 회차별 공통 이동량으로 정렬했고, 각 입력 잔차의 최대 절댓값은 11.56ms였다. 고정 이동량은 키 오버레이 표시 지연을 포함할 수 있으므로 물리 입력의 절대 지연을 입증하지 않는다. 다만 회차 연결과 입력 간격에는 부합하며, 실험 중 후반으로 갈수록 로그 시계가 100ms씩 틀어졌다는 근거는 없다. 색상 검출에서 누락된 EX02 3타도 영상 14.1초에 Space 눌림 표시를 육안으로 확인했다. 자동 검출 누락을 실제 입력 누락으로 해석하지 않았다.

영상의 문구 템플릿 점수가 0.68을 처음 넘는 프레임과 위 정렬로 추정한 원점의 차이는 −39~+16ms다. 실제 클라이언트 1920을 캡처한 감지와 720 영상 재판독, 게임 캡처/키 표시 경로가 다르므로 이 값을 새 보정 상수로 사용하지 않는다. 문구가 옅게 나타나는 프레임과 충분한 모양을 갖춘 감지 가능 프레임도 구별해야 한다. 감지 확정/첫 레인 표시의 대기 시간은 원점에 중복 더하지 않는다.
