## 현재 상태 — 2026-09-24

사용자가 태양의 잔불 두 형태를 우선 확장 대상으로 승인했다. 9월23일 수동 실험 후 **기본은 레미엘 → 벨리나 → 프로미아, 프로미아 시작**으로 변경했다. **융합은 레미엘 → 벨리나 → 아리아, 아리아 시작**을 유지한다. 기본의 시작 E1회는 자동화하고, 융합의 문구 이전 전투는 수동으로 진행한다. 외형과 동작의 차이는 각각의 영상으로 구분한다. 악몽에 묶인 자·엽석연의 연속 패링은 이번 범위가 아니다.

## 공개 후 융합 진입 판정 조정 — 2026-09-24

사용자가 실제 체감보다 웹 판정이 엄격하다고 보고하여 **융합 진입 RMB의 웹 구간만2025–2275ms**로 양끝25ms씩 확대했다. 기준2150ms·대표 영상 원점·후속1~4타는 유지한다. 아래 실측 기반 채택값2050–2250ms와 원시 결과·실험 프로필은 변경하지 않는다. 추가한 두25ms 구간의 실제 게임 성공은 미검증이며 이후 실제 플레이로 확인할 서비스 조정이다.

이번 확정 실험의 융합24회에서 **2000ms는 실행 기록이 없고, 2300ms는36·53회 모두01111로 진입 실패**다. 뒤4타의 성공이나 최종 완벽 표시를 진입 성공으로 세지 않는다. 앞선9월23일 수동 영상의 진입 무피격 관측은2100/2117/2150/2233ms이며 정확히2000/2300ms 성공 근거가 아니다. 이번 확대는2000/2300 성공 기록에 근거한 재측정 결과가 아니라 사용자가 요청한 웹 연습 여유다.

### 채택 근거·혼재·추가 측정 판단

- **기본:** 15·20회 `2200/4500/6850/7800`, 27회 `1900/4900/6500/8150`이 전체 성공이다. 30회 최종 기준도 전체 성공이고 대표 영상과 일치한다. 6450은 채택한 진입1900에서도 실패(8·29회), 4950은1타 실패(28회)다. 7750은 성공(16회)과 선행 성공 뒤 실패(19회)가 혼재해7800을 택했다. 8200은 성공과 실패가 있어8150으로 좁혔다.
- **기본 혼재 유지:** 25·26회는 같은 `1900/4850/6500/8150`에서1110/1111이다. 27회는1타만4900으로 바꾸고1111이다. 진입2200도18회 실패가 있지만15·20회 성공이다. 18회의 입력 제출 끝 지연이 약14ms였다는 관측만으로 실패 원인을 확정하지 않는다. 6500의 실패는 진입1850 등 조건도 다르므로 채택 조합1900의 성공과 함께 해석한다.
- **융합:** 41회 `2250/5100/7550/9350/11400`, 50·52회 `2150/5500/7150/9750/10950`, 43회 `2050/5300/7150/9750/11050`이 전체 성공이다. 54회 최종 기준은 영상까지 전체 성공을 확인했다. 5050·7600·11450에서 해당 동작 실패가 있어 그 안쪽을 택했다. 51회3타9800은 성공했지만4타10950이 실패했고, 50·52회3타9750에서는 마지막까지 성공하므로 앞뒤 간격을 보존한다.
- **융합 혼재 유지:** 34·35회 같은 입력에서10101/11111이며1타5100은 무조건 성공 경계가 아니다. 진입2050도43~46회 성공과47회 실패가 혼재한다. 뒤의1타5500 변경이 앞선 진입 실패의 원인이라고 해석하지 않는다. 선행 실패 뒤 결과를 각 동작의 독립 경계로 사용하지 않는다.

따라서 채택값은 특정 경로에서 반복 연습에 사용할 **실용 범위**이며 내부 최대 허용 구간이나100% 성공 보장이 아니다. 사용자의 최종 설정은 반복된 바깥 실패와 양끝 교차를 반영하고 있고, 혼재만 없애려 같은 실험을 반복하거나 전체 폭을 일괄 축소할 근거는 부족하다. 독립 읽기 전용 검토도 이 조건부 채택과 추가 필수 측정 없음에 동의했다. 다른 거리·파티·지원 경로에서 재현되는 새 반례가 생기면 해당 동작과 선행 조건만 다시 본다.

54회 중52회는 OBS 원관측UNKNOWN을 정책상OFF로 분류했고, 실제OFF 관측은25회, ON은24회뿐이다. 이를52회의 독립적인 실제 비녹화 증거라고 부르지 않는다. 30·54회에는 실제 녹화가 있으므로 로그의OFF 표시는 영상 부재 근거가 아니다. 원시 감지·입력·녹화 필드는 변경하지 않았다.

### 웹 반영 검증

타입 검사·단위108개·빌드, 보스 전환/쿠사리쿠 준비 회귀/기본4동작 완주/융합5동작 완주/모바일 터치의 브라우저5개가 통과했다. 기본 제공 프로필은 각9개 시간표·편집기 스냅샷 검사를 통과했고 실제 게임 입력은0회다. 공식 기록 저장소의 ID·해시 검사도 통과했다. 독립 읽기 전용 최종 검토에서 구간·원점·기본 준비/E 범위·실제 교대 경로·혼재 해석의 불일치를 발견하지 못했다.

최초 기본 서비스 인코딩에서 마지막1프레임이 누락되어60fps 고정 프레임 시계로 다시 인코딩했다. 최종 기본718·융합810프레임을 모두 디코딩하고, 완성 파일에서 준비/진입/후속 입력 점등을 다시 읽어 원본 컷 기준 예상 프레임과 정확히 일치함을 확인했다. 재인코딩 뒤 자산·프로필·근거 연결 단위26개도 다시 통과했다. 준비·완료 화면과 모바일 터치 화면을 확인했다. 이 검사는 웹 구현·영상 정렬의 근거이며 실제 게임의 모든 경계 성공이나 학습 효과를 입증하지 않는다.

이하9월23일 조사·설치 수치는 당시 탐색 이력이며 현행 서비스 값은 위 표를 따른다.

## 재사용과 범위

기존 제어스킬의 진입/후속 역할과 마지막 회피→QTE 해석, 공통 실험기·수동 WASD·비채점 보조 입력·기록 import·영상 정렬·웹 판정을 재사용한다. 일반 패링과 소환체 패턴까지 하나의 제어스킬로 합치지 않는다. 추가 입력은 실제 시작 경로에서 필요할 때만 설정한다.

초기 입력 후보는 외부 시연의 문구/전조/반응 위치와 내부 상태 연결, 기존 보스의 성공·반례를 함께 사용한다. 내부 일반·HC에서 상태명과 수신 구간 차이가 확인됐지만 이를 실시간 ms나 물리 입력의 성공 폭으로 환산한 것은 아니다. 전체 기준 성공 후 부족한 동작의 양끝·선행 관계만 탐색하며, 두 형태가 공유하는 근거는 조건을 붙여 재사용한다.

현재 출발 근거는 [보스 조사](../boss-control-patterns.md)와 [보존 내부 설정](../evidence/boss-control-patterns-20260918.json)의 Mutant 두 관리자다. 새 조사의 관측·추정·실험 준비 결과는 이 문서와 연결된 근거에 갱신한다. 작업 경로와 책임은 [README](../../README.md)를 따른다.

## 내부 연결과 비교

설치 원본의 한 능력 번들에서 `Mutant_AidTriggerControl`, `Mutant_HC_Init`와 일반·HC 관리자를 추출했다. `Monster_Mutant`는 일반 관리자, `HardCore` 태그가 있는 `Monster_Mutant_HC`는 Init에서 `Bool_IsHC=true`와 HC 관리자를 함께 적용한다. 후자의 공식 영문 키는 `Integrated - Phaethon of the Scorched Horizon`이다. 따라서 내부의 HC는 융합형에 연결되며, ‘절망’이라는 모드 이름만으로 형태를 판정하지 않는다. 출처·해시·객체 ID는 [내부 근거](../evidence/sun-internal-20260923.json)를 따른다.

| 내부 경로 | 진입 지원 구간 | 후속 지원 구간 | 다음 구간까지의 내부 간격 |
|---|---|---|---|
| 일반 `Attack_Execute_01_Combo` | Pre 154–184 | 64–94, 167–197, 220–250 | 73, 23 |
| HC `Attack_Execute_01_Combo_02` | Pre 159–189 | 117–147, 220–250, 335–365, 411–441 | 73, 85, 46 |

모두 상태별 **내부 좌표**이며 ms가 아니다. 후속 구간 간격은 다음 시작−직전 끝이고, Pre와 Combo의 숫자를 이어붙이지 않는다. 첫 후속은 모두 PowerStruggle을 포함하지만 일반은 Light, HC는 Heavy 태그를 사용한다. 이 구조는 일반 후속3회·HC 후속4회의 후보를 주며 내부 event 수만으로 실제 물리 입력 수를 확정한 것은 아니다.

## 문구와 시간 원점

두 외부 영상에는 기존 공용 템플릿과 같은 한국어 첫 제어기 안내가 보인다. 다만 영상의 잘림·배율·전투 중 화면 변화 때문에 같은 ROI를 단순히1280×720으로 정규화한 재생 검사는 모두 실패했다. 일반형의 최고 일치 점수는 약0.24, 융합 후보는 약0.43으로 기준0.68 미만이었다.

영상에 한정한 위치·배율 보정 뒤 일반형도 최고0.662로 미검출이었다. 융합 후보는 클립7.4667초에서 일치했으나, 육안 출현3.7초보다 약3.77초 늦으므로 **최초 문구 감지 검증으로는 실패**다. 넓은 허용 범위의 탐색 CLI가 반환한 `passed`를 실제 원점 검증으로 채택하지 않는다. 프로그램의 ROI·템플릿·기준점수는 이 잘린 영상에 맞춰 변경하지 않는다.

일반형 정밀 클립은 원본4초부터, 융합 후보는28초부터 시작한다. 일반은 클립3.43~3.45초부터 안내가 희미하게 나타나고 약3.55초에 읽히며, 융합 후보는3.68~3.70초부터 나타나 약3.85초에 읽힌다. 후보 비교에 쓰는 임시 육안 원점3.55/3.85초는 실제 실험기의 첫 일치 시각과 같다는 뜻이 아니다. 첫 사용자 녹화에서 감지 이미지·최초 일치·실제 입력과 함께 교정한다. 확인40ms 뒤의 시각을 첫 일치로 대체하지 않는다.

### 시작 E와 비채점 준비 회피

기본의 E 점등을 읽은6개 회차에서 E→문구 최초 일치는2033~2117ms였다. 사용자 발동 관측과 합쳐 **F8 감시 시작500ms에 E1회·100ms 유지**로 설정한다. 이500ms는 E→보스 반응을 맞추는 보정이 아니라 F8 후 시작 입력을 예약하는 대기다. 파티 목록은 레미엘→벨리나→프로미아를 보존하고 시작 캐릭터를 프로미아로 둔다. 인게임 첫 슬롯을 프로미아로 순환 배치하더라도 뒤의 교대 순서는 유지해야 한다. 프로그램이 파티 자체를 편성하지는 않는다.

준비 RMB는 **문구 기준500ms·100ms 유지**를 비채점 후보로 제안한다.19:25:59의483ms 입력과 준비 무피격을 가까운50ms로 옮긴 것이다. 다른 회차에서는317/350/767/783ms에도 준비 무피격이었고367/683ms에는 피해가 있어 하나의 확정 성공 폭을 만들 수 없다. 처음에는 준비 자동 회피를 켜지 않고 E+본 대응 기준 경로를 확인한 뒤 필요하면 비교한다. 준비를 추가해도 결과는 기본4자리·융합5자리 그대로이며, 준비 피해로 진입/후속 결과를 덮어쓰지 않는다.

융합은 자동 시작 공격을 추가하지 않는다. 문구 이전 전투는 사용자가 진행하고, 프로그램을 사용할 때는 대응 키를 놓고 새 문구 출현 전에F8을 누른다. F8 이후 수동RMB/Space까지 허용하는 기능을 이번에 추가한 것은 아니며, 이미 문구가 나온 뒤F8을 눌러 그 문구를 새 발동으로 사용할 수 없다.

다음 게임 실험은 **형태별 전체 기준1회**로 시작한다. 기본은 E 자동 시작과 프로미아 조건, 융합은 정상 진입과 지정 교대 경로를 확인한다. 기준이 성립한 형태부터 이른/늦은 묶음을 비교하고, 실패 전의 정상 결과는 재사용한다. 영상21개를 같은 조건의21회 성공으로 세거나 양끝을 웹 성공창으로 반영하지 않는다.

사용자가 새 후보 시간표의 프로그램 반영도 승인했다. 실제 실행 위치의v3.11.0과 두 저장 프로필에 위 후보를 반영하고 모든 실행 셀을 기준으로 선택했다. 기본 시작E1회·파티/시작 캐릭터·꺼진 준비 회피 행을 화면에서 확인했다. 공통 가짜 입력157항목과 각 프로필9개 조합·편집기 스냅샷 검사를 통과했으며 실제 게임 입력은 보내지 않았다. 독립 코드 검토에서 진행을 막을 결함은 발견되지 않았다. 기존5개 보스 프로필·템플릿·마지막 선택은 해시로 보존 확인했다. 실행 파일/프로필 해시와 검사 요약은 위 로컬 근거의 `implementation`에 기록한다. 이 검사는 E가 실제 게임에 수용되거나 후보 양끝이 성공했다는 의미가 아니다.

## 초기 실험 계획 — 로컬 영상 확보 전 이력

형태별 프로필은 기존 형식으로 준비하며, 지정 파티와 아리아 시작·수동WASD를 사용한다. 외부 파티의 반응을 그대로 성공 입력으로 복사하지 않는다. 실제 경계를 측정하기 전 이른/기준/늦은 셀은 탐색점이며 서비스 성공 폭이 아니다.

먼저 **기본형의 기준1회**를 녹화해 공용 감지와 진입을 함께 확인한다. 문구 출현 전부터 녹화하고 기존처럼 각 동작0/1 결과를 남긴다. 감지·진입이 맞으면 둘째 형태의 진입과 기준 경로를 확인한다. 융합 후보는 외부의 진입 실패 경로와 비교해야 하므로 첫 정상 진입 녹화를 분석한 뒤 후속을 교정하며, 현재 양끝을 성공 폭이라고 보고 연속 실행하지 않는다.

감지 오차나 진입 실패가 있으면 그 지점부터 교정하며 뒤의 결과를 정상 경로의 폭 근거로 합치지 않는다. 전체 기준이 성립한 뒤 필요한 동작의 양끝만 탐색하며, 무입력9조합 검사를 실제 게임9조합 반복 요청으로 바꾸지 않는다. 이 절은 첫 사용자 자료 전의 계획이며, 현행 판단은 아래 로컬 녹화 분석을 따른다.
